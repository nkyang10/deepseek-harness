# 未认证浏览器登录页取代纯文本 401

[English](guide.md) | 中文

## 变更

`authorizeIndex` 不再用纯文本 401 响应体回复对已服务的应用根路径发起的未认证浏览器请求。对根路径（`/`、`./`）的 `GET` 或 `HEAD` 现在返回 `text/html`：所有者设置了 `passcode` 时，与之前一样是带样式的口令表单；未配置口令时，是一个自包含的登录页，把访客指引到应用的配对链接，并把口令列为所有者可启用的方式。两个页面都以相同的禁止脚本、禁止框架的 CSP 及 no-referrer 提供。

仅浏览器根路径受影响。`GET /connect` 及其 `POST`、每个 `/api` RPC 与 WebSocket 流，以及在未配置口令时的根路径表单 `POST`，仍返回 `text/plain` 的 401 响应体。

以浏览器方式请求根路径的客户端会观察到这一变化。此前从根路径读取纯文本 401 响应体的客户端，现在收到的是 HTML。

## 迁移

1. 浏览器用户无需操作：根路径现在渲染带样式的页面，取代原来的纯文本。
2. 读取根路径纯文本响应体的程序化客户端必须改为指向机器端点，它们的响应不变：用于配对交换的 `GET /connect?...` 与 `/api` RPC 面都保持 `text/plain`。
3. 确认迁移是否成功：以未认证状态请求根路径并读取 `content-type: text/html`，再请求 `/connect` 或某个 `/api` 方法并读取 `content-type: text/plain`。
